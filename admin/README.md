# 一羽成局管理后台

独立的 Vue 3 + Vite 桌面端应用，源码位于 `admin/`，与小程序共用 ani-server 的账号及业务数据。不会编入微信小程序。

## 品牌与组件升级（2026-10-11）

管理端已接入 Element Plus 中文控件与图标、ECharts 运营图表，以及 Three.js 登录页羽毛球。品牌图标复用小程序现有资产，单独存放于管理端；桌面导航支持折叠，窄屏使用抽屉。组件脚本按需导入，样式由 `src/element.ts` 显式引入，品牌变量统一在 `src/style.css`。

登录羽毛球支持鼠标跟随、拖动旋转、方向键旋转、Home 复位、空格暂停，以及界面暂停/复位按钮。触屏只接管横向拖动，纵向仍可滚动页面。减少动态效果时不自动漂浮或跟随；页面隐藏时暂停；WebGL 不支持、上下文丢失或加载失败时显示本地插画，不影响登录。

概览使用现有 `/admin/overview`：趋势为北京时间近 14 天新建球局，状态可切换球局与对局，助威积分图旁保留订单数和精确积分。个人战绩展示胜负分布和原始数据。图表提供文字/表格明细，权限、版本号及幂等请求契约沿用原逻辑。

本次已安装并同步独立 `pnpm-lock.yaml`，安装过程禁用依赖脚本。交付检查仅为当前会话静态 review；未运行构建、测试、lint、类型检查或浏览器体验，未操作数据库和真实账号。待人工验收登录/会话恢复、只读权限、提交锁、表单错误与日期、弹窗键盘、零数据图表、窄屏、3D 降级和减少动态效果。

## 初次接入

以下步骤由维护者在确认目标环境后执行；本次开发没有执行安装、数据库迁移、生成 Client、启动或构建命令。

1. 核对目标 `DATABASE_URL`，由维护者执行 `pnpm prisma:deploy`、`pnpm prisma:generate`。本次追加迁移 `20261011020000_badminton_rbac`，在原有 `sys_permission / sys_role / sys_role_permission / sys_user_role` 中补入羽毛球权限和两个默认角色。此前的 `20261011010000_badminton_admin` 保留不改，兼容已应用的迁移历史。未执行过迁移的环境会依次应用两份。
2. **已有有效 `admin` 角色的邮箱账号可以直接登录**；有效权限含 `*` 或 `admin` 的角色也按现有约定识别为超级权限。普通账号需具有 `bm:admin:enter` 和所需模块权限。已停用、已删除、没有邮箱密码的账号无法通过本后台登录。微信账号可先在小程序「我的 → 邮箱与密码」（头像资料下方）验证邮箱并设置密码，用户 ID、比赛、积分和角色保持不变。
3. 如果没有任何超级管理员，可由服务器维护者在后端目录明确执行 `pnpm badminton:grant-admin <现有用户ID> --confirm`。该命令给已有邮箱账号关联系统 `admin` 角色（全局超级权限），不会创建默认密码、不会在启动时自动执行。已有管理员时优先从页面分配角色。`BADMINTON_ADMIN_IDS` 已不再参与鉴权；原先仅在该变量中的账号需转为系统角色关联。
4. 超级管理员登录「角色与授权」：在「系统角色」配置业务权限，在「用户授权」搜索已有账号并勾选角色。支持多角色，取消全部角色可撤销授权。预置 `bm_operator`、`bm_viewer` 分别为运营和只读角色，可作为新角色的配置参考。
5. 前端根目录执行 `pnpm install:admin`，然后执行 `pnpm dev:admin` 访问 `http://127.0.0.1:5174`。接口域名共用小程序在项目根目录中的环境配置；如需单独覆盖后管开发代理，可在 `admin/.env.local` 设置 `ADMIN_API_TARGET`。`pnpm build:admin` 输出 `admin/dist`，`pnpm preview:admin` 预览构建产物。
6. 小程序连接同一后端，在「我的 → 消息中心」查看已发布内容。

旧 `badminton_admin` 表仅保留历史记录，运行时代码不再读取。迁移会把该表中启用的运营/只读授权关联到新建的系统角色，不迁移停用授权，不删除原记录。迁移预留 `bm_operator`、`bm_viewer` 角色编码及名称；如环境已存在同名自定义角色，需由维护者先解决命名冲突，迁移不会静默扩权或覆盖它们。

## 权限配置

权限始终来自现有系统表；后管菜单按查看权限显示，按钮按操作权限显示，后端独立校验每个请求。没有模块权限时展示明确空态。重新聚焦页面、授权保存后或接口返回 403 时刷新当前权限。

| 模块 | 查看权限 | 操作权限 |
| --- | --- | --- |
| 后台入口 | `bm:admin:enter` | 必须同时分配所需模块查看权限 |
| 概览 | `bm:overview:read` | — |
| 球局 | `bm:match:read` | `bm:match:write`（配置、名单、排赛、状态、分享）；`bm:match:score`（录分、纠错、取消对局、结束助威） |
| 球友 | `bm:user:read` | `bm:user:write`；`bm:points:adjust`（人工调积分） |
| 积分、助威、签到 | `bm:points:read` | — |
| 公告通知 | `bm:publication:read` | `bm:publication:write`（草稿）；`bm:publication:publish`（发布、撤回） |
| 角色与授权 | `bm:access:read` | `bm:access:write` |
| 日志 | `bm:logs:read` | — |
| 服务设置 | `bm:settings:read` | `bm:settings:write` |

例如录分员可配置 `bm:admin:enter`、`bm:match:read`、`bm:match:score`，无需授权球局配置或积分调整。权限字典由原系统维护；角色编辑展示已有有效权限项，羽毛球权限由迁移提供，不允许通过界面任意创造不对应接口的业务权限。


## 生产接入

管理员在项目根目录执行 `pnpm build:admin`（或在本目录执行 `pnpm build`），将 `admin/dist/` 发布为 HTTPS 静态站点。后管与小程序共用项目根目录的 `VITE_BADMINTON_ORIGIN`，该值只填写接口域名，不包含 `/ani-server` 前缀。

| 使用方式 | 接口地址来源与行为 |
| --- | --- |
| `pnpm dev:admin` | 加载根目录开发环境配置，请求同源 `/ani-server/...`，由 Vite 代理到 `VITE_BADMINTON_ORIGIN`；当前为 `http://127.0.0.1:3000` |
| `pnpm build:admin` | 默认加载根目录生产环境配置；当前 `.env.production` 配置为 `https://api.anixuil.com`，构建产物直接请求 `https://api.anixuil.com/ani-server/...` |
| `pnpm preview:admin` | 使用构建时写入的接口地址，默认生产构建仍连接生产后端，不会切回开发代理 |

环境变量遵循 Vite 优先级：命令行环境变量高于 `.env.[mode].local`、`.env.[mode]`、`.env.local`、`.env`。如需更换生产接口，在根目录 `.env.production` 或 `.env.production.local` 修改 `VITE_BADMINTON_ORIGIN`，然后重新打包；小程序也共用此配置。`admin/.env*` 中的 `ADMIN_API_TARGET` 仅覆盖开发代理，`ADMIN_BASE` 控制静态资源路径；部署到子路径时按需设置 `ADMIN_BASE`，导航使用 hash。

后管页面与接口域名不同时，线上后端的 `CORS_ORIGINS` 必须加入后管页面的完整 origin（协议、域名、可选端口，不含路径），保留其他已允许的来源。后端已允许 `Content-Type`、`Authorization` 和 `Idempotency-Key` 请求头。通过本地预览连接生产后端时，也需要允许实际预览来源。以上为源码配置，尚未核验线上跨域白名单或进行接口联调。

## 权限与数据一致性

- 复用系统 `admin` / 通配符语义，普通角色不根据名称或硬编码身份自动提权。
- 授权操作者只能修改和授予自身已有权限范围内的角色，不能编辑自身正在使用的角色或修改自己的角色关联。系统 `admin` 角色在页面只读；超级管理员可给其他账号分配该角色。
- 角色编辑和用户授权均有快照冲突检查、幂等请求和审计日志。权限取所有有效关联的并集，已删除的用户关联、角色、角色权限关联和权限项均不生效。
- 两个登录入口的接口鉴权统一每次从数据库读取权限，避免旧 Redis 权限缓存造成撤权延迟。后管授权修改后清理旧用户信息/菜单缓存，失败时保留幂等重试；只有通过后台守卫的调用可进入管理作用域，普通小程序接口不会获得跨组织者权限。比赛操作记录真实管理员 ID，不冒用组织者身份。
- 球局仍使用原有版本号与幂等事务，比分纠错与取消仍调用现有结算服务。人工积分调整采用相同钱包锁顺序，追加独立流水，不直接篡改历史订单。
- 客户端遇到网络错误/超时，将后台写入的幂等键保留在当前标签页 sessionStorage，刷新页面后重试相同内容仍沿用原键；确认成功后清除。改变操作内容会生成新键。收到版本冲突后关闭表单并刷新数据，再重新编辑。
- 管理会话存于当前标签页的 sessionStorage；退出会注销当前服务端会话。停用羽毛球账号会让现有会话在下一次请求失效，并阻止重新登录，不改动其他平台的全局删除字段。
- 全员内容对未来加入用户同样可见；指定用户内容最多 100 人。已读人数是去重读取人数，不等于外部渠道送达人数。

## 原系统接口衔接

当前启动入口仍为 `BadmintonModule`，后管通过 `/admin/*` 适配现有系统表，不加载完整 `AppModule` 的其他业务和定时任务。原 JWT 入口的 `PermissionsGuard` 共用数据库权限解析；补齐角色、权限、用户授权、菜单管理接口的权限注解。原用户管理的跨账号资料修改需 `sys:user:update`，角色分配另需 `sys:user:assign`；公开注册不会接收角色或透传 Prisma 关联字段。原权限字典写入限定超级权限，避免通过重命名权限编码绕过授权范围。

本次仅静态 review，未实际安装、启动、构建、测试或执行迁移/授权脚本，没有修改真实用户角色。运行验收仍需在维护者确认的环境进行。

## 微信账号开通邮箱登录

小程序「我的 → 邮箱与密码」（头像资料下方）输入真实邮箱，获取 6 位验证码并设置 8–72 位密码。密码 UTF-8 编码不得超过 72 字节。验证码有效期 10 分钟，错误最多 5 次；重新发送间隔 60 秒，同一账号 24 小时最多发送 5 次、同一邮箱最多 10 次。已属于其他账号的邮箱不会自动合并；首次绑定流程不会覆盖已有邮箱密码；修改密码使用同页的独立表单。

后端沿用现有邮件配置：`EMAIL_HOST`（默认 smtp.qq.com）、`EMAIL_PORT`（默认 465）、`EMAIL_SECURE`（默认 true）、`EMAIL_USER`、`EMAIL_PASS`（邮箱 SMTP 授权码）。未配置账号和授权码时页面会显示服务未配置，验证码不会以日志或接口明文返回。

绑定后可以在该页复制用户 ID，再由维护者执行 `pnpm badminton:grant-admin <用户ID> --confirm`，或由已有管理员分配角色。开通邮箱登录本身不授予后台权限。此功能不新增数据库表；仍需先完成后台已有迁移。Node 23 的 engine 警告与缺少邮箱密码的业务报错是两回事，项目声明的运行环境为 Node 22.x。

已开通邮箱登录的账号，在同一页面输入当前密码、新密码及确认密码即可修改密码。修改密码不改变邮箱、用户 ID 或角色，也不会注销现有登录会话；下次邮箱登录使用新密码。此入口不是忘记密码重置入口。
